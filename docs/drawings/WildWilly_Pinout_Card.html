Verify before you crimp

Four checks, each of which has already cost a session on this rover.

  1. Confirm the overlay mapping. dtoverlay -h uart2-pi5 must report GPIOs 4–5, and uart4-pi5 must report 12–13. The wrong overlay does not error — it boots clean and puts the UART on pins nothing is wired to, so the device reads as dead hardware. That cost a full session on the SEN0628. If uart4-pi5 is not GP12/GP13, the next candidate is uart5-pi5 on GP16/GP17.
  2. Meter all six green wires first. Phase B reads dead on all six channels today. Six wheels failing on exactly the odd pin is one wiring pattern, not six faults — and the reverse-polarity event of 2026-09-18 may have taken those output stages. Settle it on the bench, not through a new UART.
  3. ECHO junctions at 3.2–3.4 V under servo load, not idle. Mandatory now rather than advisory: ECHO crosses from the sonar rail's reference to the Pi's once Pico B owns it.
  4. Fuse and Schottky fitted on both VSYS feeds before either board sees rover power. Pi header 5 V is unfused and sits across Witty Pi's output; and reflashing a rover-powered Pico over USB pushes 5 V back onto that rail through the VBUS→VSYS diode.
